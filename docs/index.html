The product contract

Fast when simple. Explicit when powerful.

JBar separates everyday launching, natural-language file finding, reviewed copy organization, and development into distinct capability layers.

⌕

Launcher-owned local index

Search app names, localized aliases, pinyin, filenames, extensions, dates, and bounded metadata without relying on Spotlight for interactive results.

↗

Useful file actions

Local results open quickly. Assistant results select on one click, open on double-click, and provide Open, Reveal in Finder, and Copy Path.

⧉

Copy-only organization

Original files never move, rename, change, or disappear. Existing destinations are never overwritten, including when a collision appears after preview.

拼

Chinese and pinyin

微信, weixin, and wx can find localized apps. Both ASCII and full-width workflow symbols are recognized.

40

Bounded and complete

Normal results are scrollable and bounded. Copy Organize refuses more than 40 matches or any incomplete index so every proposed action remains reviewable.

⌁

Narrow permissions

No Accessibility, Input Monitoring, or Full Disk Access. JBar uses ordinary folder consent and exposes permission/index gaps instead of hiding them.

Assisted workflows

Codex plans. JBar decides what is allowed.

A submitted prompt never becomes a shell command or an unbounded file capability. Typed plans are validated before local execution.

Settings

Simple menu. Precise JSON when you need it.

Open the menu-bar item for everyday controls or press ⌘, to edit the hot-reloaded configuration. Invalid changes keep the last-known-good settings.

Configuration file

~/.config/jbar/config.json
or $XDG_CONFIG_HOME/jbar/config.json when the environment value is absolute.

Missing keys use defaults. The generated file includes complete app roots, excluded paths/names, and downranked names. Changes that affect index scope invalidate the old snapshot.

Privacy and safety

Small capabilities, visible boundaries.

JBar is designed so a natural-language request does not silently become broad file access, destructive mutation, or an arbitrary tool call.

Local first is a behavior, not a slogan.

The local launcher, persistent index, ranking, path browsing, and frecency remain on the Mac. Only an explicit submitted assisted request starts Codex.

No document contentsThe persistent index stores filename and path metadata, not file contents.
No path disclosure in AssistantCodex creates the plan; JBar searches and exposes exact paths locally.
No destructive organizeCopies only, exclusive destinations, no overwrite, and no original mutation.
No silent incomplete resultDenied paths, crawl caps, cancellation, or more than 40 organize matches stop the workflow.
Isolated ChatGPT stateJBar uses its own Codex home and no API-key or alternate-provider fallback.
No elevated input permissionThe Carbon hotkey avoids Accessibility and Input Monitoring access.
Codex-backed workflows use the signed-in user's Codex allowance or credits and require the official Codex CLI 0.149.0 or newer. JBar does not bundle Codex, read its OAuth token, or add a separate AI charge.

Honest boundaries

Know which search tool you are using.

Spotlight searches document contents across a macOS-managed scope. JBar searches names and bounded metadata across roots you configure. They solve different problems.

JBar is best for

  • opening apps by acronym, alias, or pinyin
  • finding files by name, type, date, and bounded size
  • safe reviewed copy organization

Spotlight is best for

  • phrases inside PDFs and documents
  • OCR and system-managed metadata
  • content search outside JBar's configured roots

Still a preview

  • ad-hoc signed, not notarized
  • physical IME and complete OS/CPU release matrix pending
  • published builds may trail current source
