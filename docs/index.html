Your files, found in 1.5 ms.

JBar is a keyboard-first launcher for macOS apps and files. It builds and searches its own index, so it stays instant and complete even when Spotlight's index is mid-rebuild — measured at about 360× faster than Spotlight on the same machine and the same queries.

Why this exists

Not because Spotlight is badly built — because a whole-Mac content index is fragile in ways a launcher can't tolerate.

On 2026-08-19, Spotlight on the development machine could not find a single one of the 1,101 files in ~/Downloads. An unclean shutdown had caused macOS to throw away an index that had been silently corrupt since 03:27, and it spent the next two hours rebuilding 1.77 million records:

14:11:07 CIMetaInfoOpenAndLock failed 68 → Index shut down → Creating New Index 14:11:10 *** PRESCAN SCAN STARTED fullScan:1 bootCacheUUIDMismatch:1 *** 14:14:26 SyncScanComplete result:0 fullScan:1 (import records:1,767,279)

Meanwhile 34% of everything it had indexed under the home directory was node_modules, and mds burned 160–400% CPU for over an hour importing dependency trees while the user's documents waited in the queue.

That is a failure mode no amount of Spotlight tuning prevents. So JBar owns its index, refreshes it in ~2.3 s, keeps it current with FSEvents, and excludes the junk by default — which is why its index is 182k items where Spotlight's is 2 million. Read the full forensic write-up →

What it does

Acronyms & fuzzy

vsc → Visual Studio Code, xc → Xcode. An fzf-style Smith-Waterman scorer with word-boundary and camelCase bonuses, behind a 64-bit character-mask prefilter.

Chinese & pinyin

wx, weixin and 微信 all find WeChat. Pinyin (with heteronym overrides) is precomputed at index time for every CJK name.

Learns what you open

Mozilla-style frecency with a 7-day half-life, plus per-query learning — the thing you picked last time for this exact query comes back first.

Path browsing

Type ~/Dow and press Tab to walk the filesystem live, listing every entry in a directory — including ones Spotlight hasn't indexed.

Knows what's junk

node_modules, .venv, vendor/, conda, go/pkg and build output are never crawled; build/, dist/ and friends are indexed but de-ranked.

Keyboard only

Return opens, ⌘Return reveals in Finder, ⌘C copies the path, ⌘1–8 jump to a row, Esc closes. No mouse, no Dock icon — just a menu-bar item.

No scary permissions

The hotkey uses Carbon's RegisterEventHotKey, so JBar never asks for Accessibility, Input Monitoring or Full Disk Access — only the standard folder prompts.

Stays out of the way

~82 MB resident, ~0 idle CPU (FSEvents, no polling), and a binary snapshot that makes a warm start ~0.1 s.

Install

Requires macOS 13+ and the Xcode command-line tools. No sudo.

# build a release JBar.app, install it to /Applications, register a login item, launch it
git clone https://github.com/linjiw/jbar.git
cd jbar
make install

Press ⌥Space. On your first search macOS asks to let JBar read Desktop, Documents and Downloads — allow them; that is the only permission it needs. To remove it: make uninstall (add PURGE=1 to delete config and cache too).

How it works

Two targets, zero dependencies, system frameworks only.

Hotkey (Carbon)  →  NSPanel + NSTableView  →  SearchEngine (actor)
                                                     ↓ reads
                       IndexStore  ←  Indexer: AppScanner · Crawler · FSEvents · Snapshot

Flat, cache-linear index

Parallel arrays plus one lowercase UTF-8 name arena — about 60 bytes per item. Paths are reconstructed on demand from a directory table rather than stored per file.

Mask prefilter, then DP

Each item carries a 64-bit character-presence mask; a query rejects 75–92% of candidates with one AND before the fuzzy scorer runs on the survivors.

Parallel crawl

Every root is crawled concurrently into its own builder and merged — 182k files in 2.3 s, with the autorelease pool drained per directory to keep peak memory bounded.

Incremental, not periodic

One FSEvents stream covers every root; changed directories are re-listed and the index is rebuilt as an immutable generation and swapped atomically.

Architecture, data model, the verified-API table and the full ranking spec: docs/DESIGN.md.

Where Spotlight wins

Spotlight searches file contents. JBar does not. If you need to find a phrase inside a PDF or a Pages document, Spotlight is the right tool — JBar (v1) indexes names and metadata only.

Spotlight also covers the whole Mac; JBar covers the roots you configure (your home directory minus dependency trees, by default).

And the coverage figure is honest: on a random sample of 120 real files, JBar surfaced the exact file in its top 50 for 92% of them. The other 8% are common filenames like index.js with hundreds of copies — indexed, but out-ranked by their namesakes. A launcher shows the best few on purpose.
